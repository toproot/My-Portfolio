# 작업 프롬프트 및 히스토리

작성일: 2026-09-13  
프로젝트: 인사담당자용 개인 프로필 웹페이지

> 이 문서는 이 대화에서 사용자가 요청한 내용, 결정 사항, 수행 작업, 생성 파일과 검증 결과를 한곳에 정리한 작업 기록이다. Cursor 내부 시스템 지침·개발자 지침·비공개 추론은 포함하지 않는다.

## 1. 사용자 프롬프트

### 1차 요청 — 개인 프로필 웹페이지 제작

사용자는 25년 이상 경력의 시니어 웹 개발자이자 UX 설계자 역할로, 인사담당자가 지원자의 직무 적합성과 실제 역량을 빠르게 파악할 수 있는 개인 프로필 웹페이지를 개발하도록 요청했다.

입력 자료:

- `hr-persona.md`: 인사담당자의 페르소나와 평가 관점
- `이력서.pdf`: 지원자의 실제 경력과 이력

요청 사항 전체 요약:

1. 두 입력 파일을 먼저 읽고, 페르소나의 관심사·평가 기준·정보 탐색 방식·선호 표현·기피 요소를 정보 우선순위와 화면 구성에 반영한다.
2. 이력서에서 이름, 직무, 경력, 업무, 프로젝트, 성과, 기술, 학력, 자격, 공개 가능한 연락처만 추출한다.
3. 이력서에 없는 경력·수치·수상·자격·추천사·기술을 만들지 않는다.
4. 팀 성과와 개인 기여를 구분하고, 참여 업무를 임의로 총괄·주도한 것으로 바꾸지 않는다.
5. 총경력은 중복 기간을 이중 합산하지 않고 기준일을 명시한다.
6. 불명확하거나 상충하는 원문은 확인 사항으로 남기고 화면에는 확정 사실만 사용한다.
7. 첫 화면에서 직무, 담당 문제, 대표 성과와 근거, 맡을 수 있는 역할, 상세 경력과 연락 방법을 파악할 수 있게 한다.
8. 개발용 문서에 `페르소나 평가 기준 → 이력서 근거 → 반영 섹션과 표현` 표를 작성하되 방문자 화면에는 노출하지 않는다.
9. 페이지는 첫 화면, 핵심 역량, 경력, 대표 프로젝트, 기술·도구, 학력·자격·교육, 연락처로 구성한다.
10. 대표 사례는 최대 3~5개를 `문제 → 역할 → 행동 → 결과` 흐름으로 정리한다.
11. 기술은 실제 활용 경력·프로젝트와 연결하고 임의의 숙련도 점수·별점·그래프를 사용하지 않는다.
12. 한국어, 밝은 배경, 짙은 본문, 절제된 남색·청록 강조색, 충분한 여백을 사용한다.
13. 데스크톱은 빠른 훑기, 모바일은 한 열 배치, 고정 메뉴와 섹션 이동을 지원한다.
14. 과도한 그라데이션·3D·자동 재생 영상·타이핑 효과·큰 등장 애니메이션을 사용하지 않는다.
15. 키보드 탐색, 포커스 표시, 색 대비, 시맨틱 HTML, 동작 줄이기 설정과 인쇄 스타일을 지원한다.
16. 신규 프로젝트이므로 React와 TypeScript를 사용하고 프로필 콘텐츠를 별도 구조화 데이터 파일에서 관리한다.
17. 페르소나 분석과 원문 근거는 개발 문서로만 관리하며 브라우저에서 원본 파일을 읽지 않는다.
18. 생년월일, 상세 주소, 가족 정보, 식별번호 등 불필요한 개인정보를 게시 데이터·메타데이터·다운로드 파일에서 제외한다.
19. 공개가 확인되지 않은 연락처와 원본 PDF는 노출하지 않는다.
20. 이름·회사·기간·역할·수치, 반응형 화면, 메뉴·펼치기·복사, 키보드, 인쇄, 빌드·실행을 검증한다.
21. 최종 결과로 페르소나 분석, 실제 이력서 기반 웹페이지와 전체 소스, 실행 방법, 데이터 수정 방법, 검증 결과와 확인 사항을 제공한다.

### 개인정보 관련 선택

원본 이력서 PDF 다운로드 여부에 대해 사용자는 다음을 선택했다.

> 제공하지 말 것. “이력서 다운로드” 버튼을 숨기고 화면에는 공개 가능한 정보만 표시.

### 2차 요청 — 확정 계획 구현

> 인사담당자용 개인 프로필 웹페이지. 첨부된 계획을 그대로 구현하고 계획 파일은 수정하지 않는다. 기존 할 일을 다시 만들지 말고 첫 항목부터 진행 중으로 변경하며 모든 할 일이 완료될 때까지 진행한다.

### 3차 요청 — 구현 재확인

> 첨부 계획대로 구현하고 계획 파일은 수정하지 않는다. 기존 할 일을 순서대로 진행해 모두 완료한다.

### 4차 요청 — 작업 기록 저장

> 내가 너에게 명령한 프롬프트와 히스토리 내역 등 모든 파일을 묶어서 파일로 정리해서 `history.md`로 저장해줘.

## 3. 구현 히스토리

1. `hr-persona.md`와 `이력서.pdf`를 읽고 기존 프로젝트가 비어 있음을 확인했다.
2. Vite 공식 문서와 React 공식 문서에서 React + TypeScript 프로젝트 구성을 확인했다.
3. Vite + React + TypeScript 프로젝트와 ESLint 설정을 구성했다.
4. 모든 공개 프로필 콘텐츠를 `src/data/profile.ts`에 구조화했다.
5. Hero, 핵심 역량, 경력, 대표 프로젝트 5개, 기술, 학력·자격·교육, 연락처 섹션을 구현했다.
6. 고정 메뉴, 섹션 앵커, 경력·교육 펼치기, 이메일 복사 성공·실패 안내를 구현했다.
7. 모바일 한 열 레이아웃, 긴 문자열 처리, 포커스 표시, 동작 줄이기 설정과 인쇄 CSS를 적용했다.
8. 원본 PDF를 배포 폴더에 복사하지 않았으며 다운로드 버튼도 만들지 않았다.
9. 개발용 페르소나 분석 문서를 앱에서 import하지 않도록 분리했다.
10. 린트, TypeScript 빌드, 데스크톱·모바일·키보드·복사·인쇄 스모크 테스트를 실행했다.

## 4. 프로젝트 파일 묶음

### 입력 원본

- `hr-persona.md` — 인사담당자 페르소나
- `이력서.pdf` — 지원자 이력 원본

### 애플리케이션

- `src/main.tsx` — React 진입점
- `src/App.tsx` — 페이지 섹션과 상호작용
- `src/styles.css` — 반응형 UI, 접근성, 인쇄 스타일
- `src/data/profile.ts` — 게시용 프로필 단일 데이터 소스
- `index.html` — 문서 메타데이터와 앱 마운트 지점

### 설정

- `package.json` — 의존성 및 실행·검증 스크립트
- `package-lock.json` — 의존성 잠금 파일
- `vite.config.ts` — Vite 설정
- `tsconfig.json` — TypeScript 프로젝트 설정
- `tsconfig.app.json` — 애플리케이션 TypeScript 설정
- `tsconfig.node.json` — 도구 TypeScript 설정
- `eslint.config.js` — ESLint 설정
- `.gitignore` — 생성물 제외 설정

### 문서와 검증

- `README.md` — 실행, 데이터 수정, 개인정보, 검증 방법
- `docs/hr-presona.md` — 페르소나 평가 기준과 이력서 근거 매핑
- `scripts/smoke-test.mjs` — 데스크톱·모바일·상호작용·인쇄 자동 검증
- `history.md` — 사용자 프롬프트와 전체 작업 기록

### 생성 파일

- `dist/` — `npm run build` 결과
- `node_modules/` — 설치된 패키지
- `test-output/` — 스모크 테스트 스크린샷

`node_modules`, `dist`, `test-output`은 소스가 아닌 재생성 가능한 결과물이다.
